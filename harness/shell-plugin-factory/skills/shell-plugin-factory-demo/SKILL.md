## What you are demoing

- A fork-scoped S4-style factory loop, not direct upstream `1Password/shell-plugins` work.
- Before: one-off manual agent prompting plus manual validation.
- After: GitHub issue target list → Tessl cloud sandbox → `tessl agent` with `author-shell-plugin` → make gates → bounded retry/escalation → audit report.
- GitHub is the visual surface: Issue request, cloud run, PR/check run, job summary, sticky comment, uploaded evidence.
- This is not a Tessl-vs-non-Tessl benchmark; it is a governed development-process demo.

## GitHub demo

1. Open with fork scope: `origin` is `tdg-ninja/shell-plugins`; no push, merge, or upstream PR is automated.
2. Show the issue template: `.github/ISSUE_TEMPLATE/5-shell-plugin-factory-demo.yml`.
3. Show that adding `shell-plugin-factory` launches `.github/workflows/shell-plugin-factory-cloud.yml`.
4. Open the `tessl - Shell Plugin Factory Cloud Run` Actions run and issue comment to show Tessl cloud sandbox execution.
5. Show the PR or branch containing the generated plugin dirs and harness files.
6. Open the `tessl - Shell Plugin Factory Demo` receipt Actions run.
7. Use the job summary as the main visual: factory result, before/after narrative, live validate evidence.
8. If on a PR, show the sticky PR comment generated by the receipt workflow.
9. Open uploaded artifacts only if someone asks for raw evidence.

## Local fallback

2. Use `bash harness/shell-plugin-factory/reset-demo.sh` for a dry-run reset.
3. Ask before `bash harness/shell-plugin-factory/reset-demo.sh --apply`.
